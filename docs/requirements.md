# 要件定義書 - レシピ管理アプリ

## 1. アプリ概要

| 項目 | 内容 |
|---|---|
| アプリ名 | myrecipe-management（仮） |
| 目的 | 個人が自分のレシピを記録・検索できるアプリ |
| 想定ユーザー | 自分（個人利用） |
| 認証 | なし（今回のスコープ外） |

前回のタスク管理アプリと同様、無料範囲・最低限の構成で作成する。
技術スタックのみ変更し、フロントエンド: Next.js / バックエンド: Ruby on Rails (APIモード) / データベース: MySQL とする。

## 2. 機能要件

### 2.1 レシピのCRUD

- [ ] レシピ一覧表示
- [ ] レシピ詳細表示
- [ ] レシピ新規登録
- [ ] レシピ編集
- [ ] レシピ削除

### 2.2 検索・カテゴリ分類

- [ ] カテゴリによる絞り込み（例: 和食 / 洋食 / 中華 / デザート など）
- [ ] キーワード検索（料理名を対象）

## 3. レシピが持つ情報（データ項目）

| 項目 | 型（想定） | 必須 | 備考 |
|---|---|---|---|
| 料理名 | 文字列 | ○ | |
| 材料 | 文字列（複数行 or 別テーブル） | ○ | 設計時に構造を検討 |
| 作り方（手順） | 文字列（複数行 or 別テーブル） | ○ | 設計時に構造を検討 |
| カテゴリ | 文字列 or 別テーブル | ○ | 検索・絞り込みに使用 |
| タグ | 文字列（複数） | 任意 | 検索・絞り込みに使用 |
| 調理時間 | 数値（分） | 任意 | |
| 人数 | 数値 | 任意 | |
| カロリー | 数値 | 任意 | |

※ 画像アップロードは今回のスコープ外（実装難易度が上がるため見送り）

## 4. 非機能要件

- 無料枠の範囲内で構築・運用できること
- 個人が学習目的で一から手を動かして実装すること（既存コードの流用はしない）

## 5. 技術スタック

| レイヤー | 技術 |
|---|---|
| フロントエンド | Next.js |
| バックエンド | Ruby on Rails（APIモード） |
| データベース | MySQL |
| デプロイ先 | 未定（実装が一通り進んだ後に検討） |

## 6. スコープ外（今回はやらないこと）

- ユーザー認証・ログイン機能
- 複数ユーザーでの共有機能
- 画像アップロード機能
- 献立管理・買い物リスト機能
