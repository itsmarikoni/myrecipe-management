# 非機能要件 - レシピ管理アプリ

[要件定義書](./requirements.md) の詳細ドキュメント。

## 1. パフォーマンス

- 明確な数値目標は設けず、目安として以下を意識する。
  - ページ表示: 体感で3秒以内に表示されること
  - 同時アクセス数: 自分一人での利用を想定し、負荷対策は行わない

## 2. セキュリティ要件

- 認証機能は設けず、URLを知っていれば誰でも閲覧・編集・削除ができる状態でインターネットに公開することを前提とする。
- そのリスクを踏まえ、最低限以下の対策を行う。
  - SQLインジェクション対策（Railsの標準的なORM機能を使う範囲で対応）
  - 通信のHTTPS化（デプロイ先の標準機能を利用）
  - APIキーやDB接続情報などの秘匿情報は環境変数で管理し、リポジトリに含めない
  - フロントエンド〜バックエンド間のCORS設定を必要な範囲に限定する
  - 簡易的なレート制限の導入を検討する（過度なアクセス・自動化されたスクレイピング等の抑制）
- 上記はあくまで基本的な対策であり、本格的な不正アクセス対策・監視体制までは今回のスコープに含めない。

## 3. 可用性・データ量

- 無料枠のインフラを利用するため、「常時稼働を保証しない」ことを前提とする（スリープ・再起動・メンテナンス等により一時的にアクセスできない時間帯が発生し得る）。
- 想定データ量は個人利用の範囲（数百件程度のレシピ）とし、大量データを前提としたチューニングは行わない。

## 4. バックアップ・復旧

- 手動での定期的な `mysqldump` によるバックアップを行う方針とする。
- バックアップファイルはローカルPCまたはクラウドストレージ（Google Drive等）に保存する。
- 自動バックアップの仕組み（cron等によるスケジューリング）は今回のスコープ外とし、思い出したタイミングで手動実行する運用とする。

## 5. 対応ブラウザ・デバイス

- PCブラウザ（Google Chrome最新版を主対象）での動作を想定する。
- スマートフォン等でのレスポンシブ対応は今回のスコープ外とする。
